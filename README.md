# Создание клиентов AmneziaWG с Mac

Схема подключения VPN: устройство → RU `178.236.242.31:4956` → SWE `147.45.77.8:4956`.

Каждому устройству нужен отдельный клиентский конфиг с собственными ключами и внутренним VPN-адресом.

## Файлы

В папке `/Users/danil/Desktop/vpn` на Mac:

- `create-awg-client.sh` — запуск с Mac, создание клиента через SSH и скачивание конфига.
- `add-awg-client.py` — серверный скрипт, который нужно один раз скопировать на SWE.
- `README.md` — эта инструкция.

На SWE по умолчанию используются пути:

```text
/root/add-awg-client.py
/root/template.conf
/root/awg-clients/
```

`template.conf` — экспортированный рабочий клиентский конфиг именно SWE-сервера в формате AmneziaWG `.conf`, а не ссылка `vpn://`.

## Первоначальная подготовка

1. Включить VPN, чтобы с Mac был доступен SSH до SWE.
2. Проверить подключение через существующий алиас SSH:

```bash
ssh aeza-swe whoami
```

Примеры ниже предполагают, что алиас подключает пользователя `root`.

3. Перейти в папку со скачанными скриптами:

```bash
mkdir -p /Users/danil/Desktop/vpn
cd /Users/danil/Desktop/vpn
```

4. Скопировать серверный скрипт на SWE:

```bash
scp add-awg-client.py aeza-swe:/root/add-awg-client.py
```

5. Экспортировать работающий клиентский `.conf` от SWE, сохранить на Mac как `template.conf` и скопировать на сервер:

```bash
chmod 600 template.conf
scp template.conf aeza-swe:/root/template.conf
ssh aeza-swe 'chmod 600 /root/template.conf /root/add-awg-client.py'
```

На Mac нужны Bash и OpenSSH. На SWE — Python 3.8+, работающий Docker и контейнер AmneziaWG. Скрипт автоматически выбирает один работающий контейнер с именем `amnezia-awg*`.

## Создать клиента и скачать конфиг

Включить VPN и выполнить на Mac:

```bash
cd /Users/danil/Desktop/vpn
bash create-awg-client.sh danil-phone
```

Готовый файл появится здесь:

```text
/Users/danil/Desktop/vpn/danil-phone.conf
```

Для другого устройства использовать другое имя:

```bash
bash create-awg-client.sh danil-laptop
```

Имя может содержать латинские буквы, цифры, `_` и `-`; длина — до 64 символов, первый символ — буква или цифра.

Импортировать каждый полученный конфиг на соответствующее устройство. В конфиге автоматически устанавливается:

```ini
Endpoint = 178.236.242.31:4956
```

Конфиг сохраняется в текущую директорию терминала, независимо от расположения самого скрипта. Например:

```bash
cd /Users/danil/Desktop/vpn
bash /Users/danil/Desktop/vpn/create-awg-client.sh tablet
```

## Указать SSH-хост

По умолчанию используется `aeza-swe` из `~/.ssh/config`. Можно задать другой алиас или адрес:

```bash
bash create-awg-client.sh tablet --host aeza-swe
bash create-awg-client.sh tablet2 --host root@147.45.77.8
```

Используются обычные настройки SSH, ключи, SSH-agent и запросы пароля. Подключение идёт напрямую до SWE; RU-сервер используется как VPN-транзит.

## Повторно скачать существующий конфиг

Если клиент создался на сервере, но скачивание оборвалось:

```bash
bash create-awg-client.sh danil-phone --download-only
```

При другом хосте повторить тот же `--host`:

```bash
bash create-awg-client.sh danil-phone --host root@147.45.77.8 --download-only
```

Этот режим скачивает сохранённый серверный файл, не создавая нового клиента. Серверная копия остаётся в `/root/awg-clients/`.

Локальные файлы не перезаписываются. Если `danil-phone.conf` уже существует, перед повторным скачиванием переместить его или запустить команду из другой папки.

## Дополнительные параметры

```bash
bash create-awg-client.sh tablet \
  --host aeza-swe \
  --remote-script /root/add-awg-client.py \
  --template /root/template.conf \
  --remote-dir /root/awg-clients \
  --ru-ip 178.236.242.31 \
  --ru-port 4956
```

Если контейнеров несколько, указать нужный:

```bash
bash create-awg-client.sh tablet --container amnezia-awg2
```

Если автоматически не найден серверный конфиг, передать путь внутри контейнера:

```bash
bash create-awg-client.sh tablet \
  --container amnezia-awg2 \
  --server-conf /opt/amnezia/awg/awg0.conf
```

Для SSH-пользователя без root доступен `--sudo`. Он требует беспарольного sudo для вызываемых команд; локальный скрипт на Mac запускать без sudo. При необходимости задать доступные этому пользователю пути с помощью `--remote-script`, `--template` и `--remote-dir`.

Полная справка:

```bash
bash create-awg-client.sh --help
```

## Проверить клиентов на SWE

```bash
ssh aeza-swe 'docker ps --format "table {{.Names}}\t{{.Image}}"'
ssh aeza-swe 'docker exec amnezia-awg2 awg show'
```

Заменить имя контейнера, если оно другое. Если команда `awg` отсутствует, попробовать `wg` вместо неё.

Скрипт добавляет peer без перезапуска туннеля и сохраняет серверный конфиг. Перед изменением создаётся резервная копия внутри контейнера; её путь печатается при успешном создании.

Клиенты этого скрипта видны в `awg show`, но не добавляются в `clientsTable` и список управления приложения Amnezia. Не создавать и не удалять клиентов через приложение одновременно со скриптом.

Поддерживается один IPv4-туннель в выбранном Docker-контейнере. Рабочий шаблон должен соответствовать текущим параметрам SWE-сервера.

## При ошибке

- SSH не подключается: включить VPN и проверить `ssh aeza-swe` отдельно.
- Не найден серверный скрипт или шаблон: проверить пути и первоначальную подготовку.
- Имя клиента уже существует на сервере: использовать `--download-only` для получения его файла либо новое имя для нового устройства.
- Локальный файл уже существует: переместить его или перейти в другую папку.
- Ошибка после создания клиента: попробовать `--download-only`; если создание не завершилось, изучить сообщения об ошибке перед повторным запуском.

Файлы `.conf` содержат приватные ключи. Скрипт сохраняет скачанный файл с правами `600` и не выводит его содержимое в терминал.

Проверки скриптов выполнены с имитацией Docker и SSH. Запуск и работоспособность на конкретном SWE-сервере пока не проверены.

## Веб-консоль через Docker Compose

Консоль управляет существующим контейнером AmneziaWG на том же Linux-сервере. AmneziaWG устанавливается отдельно: Compose запускает только панель. Нужны Docker Engine и Docker Compose v2. Адрес текущей установки: **https://147.45.77.8:80** (HTTPS с явным портом 80). Сертификат самоподписанный.

### Новая установка

```bash
git clone https://github.com/ytowka/vpn-amnezia-ui.git /opt/amnezia-ui
cd /opt/amnezia-ui
cp .env.example .env
mkdir -p data
chmod 700 data
# Скопировать экспортированный рабочий конфиг этого VPN-сервера:
install -m 600 /path/to/working-client.conf data/template.conf
# Отредактировать .env: VPN_ENDPOINT, TLS_SAN, имя контейнера и пути.
docker compose up -d --build --wait
```

`VPN_ENDPOINT` — адрес и UDP-порт для новых клиентов (например, RU-транзит). `TLS_SAN` — IP/DNS самой админки, используется только при первом создании сертификата. `UI_PORT` по умолчанию 80; внутри контейнера HTTPS слушает 8443. `SERVER_CONF` и `CLIENTS_TABLE` — пути **внутри VPN-контейнера**. Не запускайте несколько копий панели с одной папкой данных.

При первом запуске автоматически создаются пароль, его scrypt-хеш и сертификат. Посмотреть пароль:

```bash
cat /opt/amnezia-ui/data/state/admin-password.txt
```

Все постоянные данные находятся в одной папке:

```text
data/
  template.conf               # рабочий шаблон с ключами
  clients/                    # сохранённые клиентские .conf
  state/
    admin-password.txt        # пароль для администратора
    credentials.json          # хеш пароля
    cert.pem / key.pem        # HTTPS
    disabled.json             # заблокированные peers, включая PSK
    metrics.sqlite3           # история графиков
    audit.log                 # журнал изменений доступа
```

`data/` и `.env` исключены из Git и контекста сборки Docker. Образ содержит только код. Панель использует Docker socket для управления VPN, что даёт ей административный доступ к Docker хоста. Дополнительно подключаются общий lock и read-only счётчик IP forwarding хоста; privileged и host network не используются. Привязки томов и healthcheck описаны в [документации Compose](https://docs.docker.com/reference/compose-file/services/).

### Обновление и управление

```bash
cd /opt/amnezia-ui
git pull --ff-only
docker compose up -d --build --wait
docker compose ps
docker compose logs --tail=100 console
# Остановить только админку (VPN продолжит работу):
docker compose down
```

Пересоздание контейнера не сбрасывает пароль, сертификат, блокировки или историю. После обновления может потребоваться повторный вход, поскольку сессии хранятся в памяти.

### Перенос на другой сервер

Сначала установите/перенесите сам VPN-контейнер, его серверные ключи, конфиг, маршрутизацию и транзит. Папка `data` содержит данные панели, но **не заменяет резервную копию VPN-сервера**. Для сохранения работоспособности уже выданных конфигов нужно сохранить идентичность VPN-сервера и доступность прежнего endpoint. Иначе старые конфиги потребуется перевыпустить/изменить.

На исходном сервере остановите только панель и создайте согласованную копию (включая SQLite):

```bash
cd /opt/amnezia-ui
docker compose stop console
umask 077
tar -czf /root/amnezia-ui-backup.tar.gz .env data
docker compose start console
```

Перенесите архив на новый сервер по SSH. В клонированном репозитории распакуйте его и проверьте `.env`:

```bash
cd /opt/amnezia-ui
tar -xzf /root/amnezia-ui-backup.tar.gz
# Исправить VPN_ENDPOINT, AWG_CONTAINER, SERVER_CONF, CLIENTS_TABLE при необходимости.
docker compose up -d --build --wait
```

Пароль и история сохранятся. Архив содержит приватные ключи и пароль: храните его с правами 600. Для нового IP/DNS можно оставить старый сертификат с предупреждением браузера либо остановить панель, сохранить старую пару сертификат/ключ вне `data/state`, убрать оба файла из `data/state`, изменить `TLS_SAN` и запустить панель для создания новой пары. На новом сервере также должен быть доступен TCP-порт админки.

### Переход с прежнего systemd-запуска

Для исходной установки с `/var/lib/amnezia-ui`, `/root/awg-clients` и `/root/template.conf`:

```bash
cd /opt/amnezia-ui
sh deploy/migrate-systemd.sh
```

Скрипт сначала собирает образ, затем останавливает старую панель, копирует данные, запускает Compose и ждёт healthcheck. При неудачном запуске возвращает прежнюю службу. После успеха отключает автозапуск старой службы, а `/root/awg-clients` и `/var/lib/amnezia-ui` становятся ссылками на `data/clients` и `data/state`, чтобы прежний CLI использовал те же данные. Исходные папки сохранены рядом с суффиксом `.pre-compose-*`; старый пароль `/root/amnezia-ui-password.txt` остаётся действующим. Скрипт не перезаписывает существующую `data`.

### Возможности и ограничения

Список всех peers, поиск, handshake и трафик, создание ключа/IP, скачивание сохранённого `.conf`, блокировка/восстановление и окончательный отзыв доступа. Для существующего клиента без сохранённого приватного ключа скачать конфиг невозможно. IP заблокированных клиентов не выдаются повторно. Изменения применяются без перезапуска VPN; перед правкой серверного конфига создаётся `.backup-ui-*` в VPN-контейнере. Восстановление старого конфига может вернуть отозванные ключи.

Это панель установленного AmneziaWG: установка других протоколов и генерация `vpn://` не входят в неё. Новые peers не регистрируются в `clientsTable` приложения Amnezia. Не управляйте клиентами через приложение Amnezia одновременно с панелью. Старый CLI и панель используют общий lock `/run/lock/add-awg-client.lock`. Операции требуют сессию, изменения — CSRF; пароль и конфиги не выводятся в логи.

### Графики и диагностика

Панель собирает метрики каждые 10 секунд в `/var/lib/amnezia-ui/metrics.sqlite3` и хранит последние 24 часа независимо от открытого браузера. Можно выбрать весь туннель или отдельного клиента, период 1/6/24 часа. Приём/отправка показываются со стороны сервера. Для клиентов скорость считается по разнице байтовых счётчиков AWG, для всего туннеля дополнительно доступны пакеты/с из счётчиков сетевого интерфейса. Персонального счётчика пакетов у AWG нет; правила firewall для учёта не добавляются. Общее значение интерфейса и сумма клиентов могут отличаться из-за особенностей учёта. После перезапуска peer/туннеля, пропуска замеров или сброса счётчиков график содержит разрыв. Значения для длинных периодов усредняются. Первые значения появляются после двух замеров; старой истории до установки сборщика нет.

Кнопка «Проверить соединение» запускает проверки контейнера, интерфейса, IP forwarding хоста и контейнера, маршрута, NAT и ping 1.1.1.1 из контейнера. Для выбранного клиента дополнительно проверяются наличие peer, handshake, двусторонние байтовые счётчики и ping его VPN IPv4 /32 из подсети туннеля. Отчёт скачивается в `.txt`. Проверки только читают настройки, не исправляют их автоматически. Недоступный ping может означать фильтрацию ICMP или сон устройства; успешный ping с сервера не доказывает работоспособность UDP-проброса через RU и интернета на устройстве клиента. Диагностика требует входа и CSRF-токена и запускается не чаще одного раза в 10 секунд.
