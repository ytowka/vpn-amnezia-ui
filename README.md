# Создание клиентов AmneziaWG с Mac

Схема подключения VPN: устройство → RU `178.236.242.31:4956` → SWE `147.45.77.8:4956`.

Каждому устройству нужен отдельный клиентский конфиг с собственными ключами и внутренним VPN-адресом.

## Файлы

В папке `/Users/danil/Desktop/vpn` на Mac:

- `create-awg-client.sh` — запуск с Mac, создание клиента через SSH и скачивание конфига.
- `add-awg-client.py` — серверный скрипт, который нужно один раз скопировать на SWE.
- `README.md` — эта инструкция.

На SWE по умолчанию используются пути:

```text
/root/add-awg-client.py
/root/template.conf
/root/awg-clients/
```

`template.conf` — экспортированный рабочий клиентский конфиг именно SWE-сервера в формате AmneziaWG `.conf`, а не ссылка `vpn://`.

## Первоначальная подготовка

1. Включить VPN, чтобы с Mac был доступен SSH до SWE.
2. Проверить подключение через существующий алиас SSH:

```bash
ssh aeza-swe whoami
```

Примеры ниже предполагают, что алиас подключает пользователя `root`.

3. Перейти в папку со скачанными скриптами:

```bash
mkdir -p /Users/danil/Desktop/vpn
cd /Users/danil/Desktop/vpn
```

4. Скопировать серверный скрипт на SWE:

```bash
scp add-awg-client.py aeza-swe:/root/add-awg-client.py
```

5. Экспортировать работающий клиентский `.conf` от SWE, сохранить на Mac как `template.conf` и скопировать на сервер:

```bash
chmod 600 template.conf
scp template.conf aeza-swe:/root/template.conf
ssh aeza-swe 'chmod 600 /root/template.conf /root/add-awg-client.py'
```

На Mac нужны Bash и OpenSSH. На SWE — Python 3.8+, работающий Docker и контейнер AmneziaWG. Скрипт автоматически выбирает один работающий контейнер с именем `amnezia-awg*`.

## Создать клиента и скачать конфиг

Включить VPN и выполнить на Mac:

```bash
cd /Users/danil/Desktop/vpn
bash create-awg-client.sh danil-phone
```

Готовый файл появится здесь:

```text
/Users/danil/Desktop/vpn/danil-phone.conf
```

Для другого устройства использовать другое имя:

```bash
bash create-awg-client.sh danil-laptop
```

Имя может содержать латинские буквы, цифры, `_` и `-`; длина — до 64 символов, первый символ — буква или цифра.

Импортировать каждый полученный конфиг на соответствующее устройство. В конфиге автоматически устанавливается:

```ini
Endpoint = 178.236.242.31:4956
```

Конфиг сохраняется в текущую директорию терминала, независимо от расположения самого скрипта. Например:

```bash
cd /Users/danil/Desktop/vpn
bash /Users/danil/Desktop/vpn/create-awg-client.sh tablet
```

## Указать SSH-хост

По умолчанию используется `aeza-swe` из `~/.ssh/config`. Можно задать другой алиас или адрес:

```bash
bash create-awg-client.sh tablet --host aeza-swe
bash create-awg-client.sh tablet2 --host root@147.45.77.8
```

Используются обычные настройки SSH, ключи, SSH-agent и запросы пароля. Подключение идёт напрямую до SWE; RU-сервер используется как VPN-транзит.

## Повторно скачать существующий конфиг

Если клиент создался на сервере, но скачивание оборвалось:

```bash
bash create-awg-client.sh danil-phone --download-only
```

При другом хосте повторить тот же `--host`:

```bash
bash create-awg-client.sh danil-phone --host root@147.45.77.8 --download-only
```

Этот режим скачивает сохранённый серверный файл, не создавая нового клиента. Серверная копия остаётся в `/root/awg-clients/`.

Локальные файлы не перезаписываются. Если `danil-phone.conf` уже существует, перед повторным скачиванием переместить его или запустить команду из другой папки.

## Дополнительные параметры

```bash
bash create-awg-client.sh tablet \
  --host aeza-swe \
  --remote-script /root/add-awg-client.py \
  --template /root/template.conf \
  --remote-dir /root/awg-clients \
  --ru-ip 178.236.242.31 \
  --ru-port 4956
```

Если контейнеров несколько, указать нужный:

```bash
bash create-awg-client.sh tablet --container amnezia-awg2
```

Если автоматически не найден серверный конфиг, передать путь внутри контейнера:

```bash
bash create-awg-client.sh tablet \
  --container amnezia-awg2 \
  --server-conf /opt/amnezia/awg/awg0.conf
```

Для SSH-пользователя без root доступен `--sudo`. Он требует беспарольного sudo для вызываемых команд; локальный скрипт на Mac запускать без sudo. При необходимости задать доступные этому пользователю пути с помощью `--remote-script`, `--template` и `--remote-dir`.

Полная справка:

```bash
bash create-awg-client.sh --help
```

## Проверить клиентов на SWE

```bash
ssh aeza-swe 'docker ps --format "table {{.Names}}\t{{.Image}}"'
ssh aeza-swe 'docker exec amnezia-awg2 awg show'
```

Заменить имя контейнера, если оно другое. Если команда `awg` отсутствует, попробовать `wg` вместо неё.

Скрипт добавляет peer без перезапуска туннеля и сохраняет серверный конфиг. Перед изменением создаётся резервная копия внутри контейнера; её путь печатается при успешном создании.

Клиенты этого скрипта видны в `awg show`, но не добавляются в `clientsTable` и список управления приложения Amnezia. Не создавать и не удалять клиентов через приложение одновременно со скриптом.

Поддерживается один IPv4-туннель в выбранном Docker-контейнере. Рабочий шаблон должен соответствовать текущим параметрам SWE-сервера.

## При ошибке

- SSH не подключается: включить VPN и проверить `ssh aeza-swe` отдельно.
- Не найден серверный скрипт или шаблон: проверить пути и первоначальную подготовку.
- Имя клиента уже существует на сервере: использовать `--download-only` для получения его файла либо новое имя для нового устройства.
- Локальный файл уже существует: переместить его или перейти в другую папку.
- Ошибка после создания клиента: попробовать `--download-only`; если создание не завершилось, изучить сообщения об ошибке перед повторным запуском.

Файлы `.conf` содержат приватные ключи. Скрипт сохраняет скачанный файл с правами `600` и не выводит его содержимое в терминал.

Проверки скриптов выполнены с имитацией Docker и SSH. Запуск и работоспособность на конкретном SWE-сервере пока не проверены.

## Веб-консоль AmneziaWG

Панель обслуживает существующий `amnezia-awg2` на SWE. Адрес: **https://147.45.77.8:80** (именно HTTPS, явный порт 80). Самоподписанный сертификат: при первом открытии принять его в браузере. Пароль генерируется при установке и хранится только на сервере в `/root/amnezia-ui-password.txt`; в приложении хранится scrypt-хеш. Сессия действует 8 часов. Ключи и пароли в Git не включены.

Возможности: список всех peers из текущего конфига и туннеля, имена сохранённых клиентов и реестра Amnezia, поиск, handshake и трафик, создание отдельного ключа/IP, скачивание сохранённого `.conf`, блокировка и восстановление доступа, окончательный отзыв с удалением сохранённого `.conf`. Для существующего клиента без сохранённого приватного ключа скачать конфиг невозможно.

Установка (Python 3.10+, Docker, OpenSSL, systemd, root):

```bash
git clone https://github.com/ytowka/vpn-amnezia-ui.git /opt/amnezia-ui
cd /opt/amnezia-ui
sh deploy/install.sh
```

Нужны существующие `/root/template.conf`, `/root/awg-clients/` и контейнер с интерфейсом `awg0`. Консоль использует транзитный endpoint `178.236.242.31:4956`. Перед установкой порт TCP 80 должен быть свободен. Установщик не меняет firewall и VPN-маршрутизацию.

Обновление:

```bash
cd /opt/amnezia-ui
git pull --ff-only
python3 -m unittest discover -s tests -v
systemctl restart amnezia-ui
```

Параметры через systemd override: `PORT`, `BIND`, `STATE_DIR`, `CLIENT_DIR`, `CLIENT_TEMPLATE`, `AWG_CONTAINER`, `AWG_INTERFACE`, `SERVER_CONF`, `VPN_ENDPOINT`.

Блокировки хранятся в `/var/lib/amnezia-ui/disabled.json` (содержит PSK, права 600); IP заблокированного клиента не выдаётся повторно. Перед изменениями серверного конфига создаётся `.backup-ui-*` внутри контейнера. Не восстанавливать старые бэкапы без проверки: они могут вернуть доступ отозванным ключам. Отзыв удаляет peer и из файла, и из работающего интерфейса. При перезапуске панели прерванный отзыв завершается автоматически. Счётчики трафика сбрасываются при перезапуске туннеля/пересоздании peer; «Активен» означает handshake за последние 180 секунд.

Это консоль для установленного AmneziaWG, а не полная замена приложения Amnezia: установка других протоколов, управление VPS и генерация `vpn://` не входят в эту версию. Новые peers не регистрируются в `clientsTable` приложения; при окончательном удалении существующая запись удаляется. Не управлять клиентами одновременно через приложение Amnezia и эту панель. Операции старого скрипта и панели используют общий файловый lock.

Сервис работает от root, поскольку управляет Docker. Внешних Python/JS-зависимостей и CDN нет. Все операции API требуют сессию, изменения — CSRF-токен; вход ограничен десятью неудачными попытками за 15 минут с одного IP. Секретные конфиги отдаются без кеширования. Для отключения панели: `systemctl disable --now amnezia-ui` — VPN продолжит работать.
