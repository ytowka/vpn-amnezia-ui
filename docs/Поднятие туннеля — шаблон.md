# IPv4 через IPv6: enter → exit

Выполнять от root. Настройка туннеля и маршрутов — до перезагрузки.

## 1. Параметры — на обоих серверах

Заменить все плейсхолдеры перед выполнением:

```bash
ENTER_IPV4="<ENTER_IPV4>"
ENTER_IPV6="<ENTER_IPV6>"
EXIT_IPV4="<EXIT_IPV4>"
EXIT_IPV6="<EXIT_IPV6>"
PORT="<UDP_PORT>"
```

## 2. enter — создать туннель

Если `tun6` уже есть, пропустить команду `add` и сверить адреса в проверке.

```bash
ip -6 tunnel add tun6 mode ipip6 local "$ENTER_IPV6" remote "$EXIT_IPV6"
ip link set tun6 up

# Проверка: UP, mode ipip6, правильные local/remote
ip -d link show tun6
```

## 3. enter — направить трафик в туннель

```bash
ip route replace "$EXIT_IPV4/32" dev tun6

# Проверка: dev tun6
ip route get "$EXIT_IPV4"
```

## 4. enter — разрешить входящий туннель

```bash
ip6tables -C INPUT -p 4 -s "$EXIT_IPV6/128" -d "$ENTER_IPV6/128" -j ACCEPT 2>/dev/null || \
  ip6tables -I INPUT 1 -p 4 -s "$EXIT_IPV6/128" -d "$ENTER_IPV6/128" -j ACCEPT

# Проверка: код 0
ip6tables -C INPUT -p 4 -s "$EXIT_IPV6/128" -d "$ENTER_IPV6/128" -j ACCEPT
echo $?
```

## 5. enter — настроить проброс

В каталоге с `setup-transit-v6.sh`:

```bash
sed -i \
  -e "s/^TRANSIT_IP=.*/TRANSIT_IP=\"$ENTER_IPV4\"/" \
  -e "s/^EXIT_IP=.*/EXIT_IP=\"$EXIT_IPV4\"/" \
  -e "s/^PORT=.*/PORT=\"$PORT\"/" \
  -e 's/^IFACE=.*/IFACE="tun6"/' \
  setup-transit-v6.sh

# Проверка: адреса, порт и IFACE="tun6"
head -n 7 setup-transit-v6.sh
bash -n setup-transit-v6.sh

bash setup-transit-v6.sh

# Проверка: ip_forward = 1; правила DNAT, SNAT и FORWARD присутствуют
sysctl net.ipv4.ip_forward
iptables -t nat -nvL --line-numbers
iptables -nvL FORWARD --line-numbers
```

Разрешения FORWARD должны быть выше блокирующих правил.

## 6. exit — создать туннель

Если `tun6` уже есть, пропустить команду `add` и сверить адреса в проверке.

```bash
ip -6 tunnel add tun6 mode ipip6 local "$EXIT_IPV6" remote "$ENTER_IPV6"
ip link set tun6 up

# Проверка: UP, mode ipip6, правильные local/remote
ip -d link show tun6
```

## 7. exit — разрешить входящий туннель

```bash
ip6tables -C INPUT -p 4 -s "$ENTER_IPV6/128" -d "$EXIT_IPV6/128" -j ACCEPT 2>/dev/null || \
  ip6tables -I INPUT 1 -p 4 -s "$ENTER_IPV6/128" -d "$EXIT_IPV6/128" -j ACCEPT

# Проверка: код 0
ip6tables -C INPUT -p 4 -s "$ENTER_IPV6/128" -d "$EXIT_IPV6/128" -j ACCEPT
echo $?
```

## 8. exit — сохранить текущую схему обратного пути

```bash
sysctl -w net.ipv4.conf.all.rp_filter=0
sysctl -w net.ipv4.conf.tun6.rp_filter=0

# Проверка: оба значения 0
sysctl net.ipv4.conf.all.rp_filter net.ipv4.conf.tun6.rp_filter

# Проверка текущего обратного маршрута
ip route get "$ENTER_IPV4"
```

## 9. Необязательно: exit — ответы тоже через туннель

Пропустить, если текущая схема устраивает. Затронет весь трафик к enter,
включая ответы SSH с этого адреса; нужен доступ к консоли провайдера.

```bash
ip route replace "$ENTER_IPV4/32" dev tun6

# Проверка: dev tun6
ip route get "$ENTER_IPV4"
```

Если ответы идут напрямую по IPv4, firewall enter должен разрешать их через
фактический входящий интерфейс. Правило скрипта с `-i tun6` их не покрывает.

## 10. Оба сервера — проверить подключение

Выполнить и подключить VPN-клиент:

```bash
tcpdump -ni tun6 "udp port $PORT"
```

На enter должны расти счётчики проброса:

```bash
iptables -t nat -nvL
iptables -nvL FORWARD
```

Если пакетов нет: проверить протокол 4 в firewall провайдера и IPv6 OUTPUT.
На exit UDP-порт Amnezia должен быть разрешён; при Docker проверить FORWARD/DOCKER-USER.
ICMPv6 Packet Too Big должен проходить.

## 11. Оба сервера — сохранить firewall

Если установлен `netfilter-persistent`:

```bash
netfilter-persistent save

# Проверка сохранённых правил туннеля
grep -E ' -p (4|ipencap) ' /etc/iptables/rules.v6
```

Создание `tun6`, маршруты и параметры `rp_filter` сохранить отдельно в сетевой
конфигурации или systemd: сначала сеть, затем туннель, затем его параметры и маршруты.
После перезагрузки повторить проверки шагов 2–10.
